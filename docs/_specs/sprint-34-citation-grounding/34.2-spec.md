for verbatim statute text) in surface forms Lever A.1 doesn't catch; one is a genuine grounding miss
the validator **correctly** rejects:

| # | `rejected_citation` | `cited_chunk_id` | Pattern | This sprint? |
|---|---|---|---|---|
| **P1** | `"Early Termination — early-termination-general#section:1"` | `early-termination-general#section:1` | **Label-prefixed chunk pointer** — the validated chunk_id is embedded after a `"Label — "` prefix | **Fix (D.1)** |
| **P2** | `"Attorneys' Fees Clauses"` | `attorneys-fees-clauses#section:1` (heading "One-way vs. reciprocal") | **De-slugged chunk title** — the chunk's own name, not statute text, not the heading | **Fix (D.2)** |

This is a **Source-Grounded AI** matter: a citation on a tenant's card must refer to evidence actually
retrieved for that clause. The diagnostic logs (Charity-Majors-style observability) drove the fix shape,
exactly as in 34.0/34.1.

## The principled boundary (the spec's spine)

**Accept a citation that IS the cited chunk's own identity (its pointer form OR its title form);
reject a citation that asserts external authority not present in the chunk.**

`validateGrading` already encodes two accept-cases — pointer-exact (A.1) and verbatim-in-body (A.2).
34.2 adds the two identity forms A.1 missed (P1 embedded-pointer, P2 de-slugged-title). P3 is neither
identity nor in-body, so it stays rejected **by construction** — we add no lever for it.

## Spec

Target: [`validateGrading`](../../../src/lib/tools/lease-tools.ts) (lines ~204–279) and the
`humaniseChunkPointer` slug logic (lines ~189–202). No route/API/UI/prompt changes.

### Invariants (carried — must not break)

- The retrieved-set check stays first: a `chunk_id` not in `retrieved` still rejects (`chunk_id_not_retrieved`).
- All Sprint 34.1 acceptances unchanged: exact chunk_id-as-citation, and concatenated multi-statute

- **Fabrication rejection preserved**: a citation that is neither the chunk's identity nor in its body

### Lever D.1 — embedded chunk pointer (generalises A.1)

Generalise A.1's exact check ([lease-tools.ts:241](../../../src/lib/tools/lease-tools.ts#L241)) from
`raw.statute_citation === raw.chunk_id` to `raw.statute_citation.includes(raw.chunk_id)`. The `chunk_id`
(`slug#section:N`) is already validated as retrieved and won't occur coincidentally in a real statute
string, so an `includes`-match is a grounded chunk reference in a decorated wrapper. Canonicalise to
`humaniseChunkPointer(raw.chunk_id)` (P1 → `"Early termination (NJ tenant-law corpus, §1)"`). Exact
match is a strict subset, so this is behaviour-preserving for A.1.

### Lever D.2 — de-slugged chunk title

Factor a small helper `chunkSlugPhrase(chunkId)` from the existing `humaniseChunkPointer` internals
(strip `#section:N`, strip trailing `-general`, split on `-`, join with spaces) → e.g.
`attorneys-fees-clauses#section:1` → `"attorneys fees clauses"`. Define
`normalize(s) = s.toLowerCase().replace(/[^a-z0-9]+/g, ' ').trim()`. Accept when
`normalize(raw.statute_citation) === normalize(chunkSlugPhrase(raw.chunk_id))` and canonicalise to
`humaniseChunkPointer(raw.chunk_id)` (P2 → `"Attorneys fees clauses (NJ tenant-law corpus, §1)"`).
**Exact** normalized equality only — no substring/superset — so a real statute can't accidentally qualify.

### Lever D.3 — em-dash label+statute concatenation (extends A.2)

**Added 2026-06-01 after the 34.2 live re-verify surfaced pattern P4** (folded into this slice per user
direction). The model joins a humanised label to a grounded statute with an **em-dash** instead of a
`;`, e.g. `"Late Fees on Rent — NJSA 56:8-1 et seq."` where `"NJSA 56:8-1 et seq."` IS verbatim in the
chunk body. A.2 currently splits only on `;` / `&` / ` and `, so it never isolates the grounded part.

Extend A.2's split delimiter set to also split on a **whitespace-bounded dash** — em-dash `—`, en-dash
`–`, or spaced hyphen ` - `: regex `\s+(?:and|[—–-])\s+`. The whitespace-on-both-sides requirement is
load-bearing: it leaves intra-token hyphens untouched (`NJSA 56:8-1`, `repair-and-deduct`). Acceptance +
canonicalisation are unchanged (accept if any part is in the body; canonicalise to the matched part) —
this is purely a delimiter widening, fully behaviour-preserving for the 34.1 concatenated case.

### Gate order inside validateGrading

1. retrieved-set check (unchanged → reject `chunk_id_not_retrieved`)
2. **D.1** embedded-pointer (generalised A.1)
3. **A.2 (extended by D.3)** verbatim body-part match — now splits on `;`/`&`/`and` **and** whitespace-bounded `—`/`–`/`-`
4. **D.2** de-slugged-title (last-resort identity match before rejecting)
5. else reject `citation_not_in_body` ← **P3 lands here**

## Spec QA — gaps & risks

- **Non-determinism — won't reach zero.** The same lease gave 1 ungraded (prior run) vs 3 (this sample);
  the model picks citations differently each scan. Success = "recovers the P1/P2 chunk-identity patterns
  + no regression," **not** a deterministic 0-ungraded. P3-class misses will recur.
- **P2 false-accept risk.** A citation coincidentally equal to a de-slugged slug phrase would be accepted.
  Mitigated by **exact** normalized equality + the fabrication regression test; low risk (slugs are topic
  names, not statute numbers).
- **Integrity boundary (load-bearing) — do NOT fix P3 in the validator.** Accepting external case-law
  absent from the cited chunk would betray Source-Grounded AI and the human-in-the-loop trust boundary
  (a tenant could act on an ungrounded citation). P3's real fix is retrieval/prompt-side — out of scope.
- **Prompt note.** system-prompt ~L145 tells the model to fall back to the chunk *heading*; it instead
  emits pointer/title forms. Sprint 34 deferred Lever B (prompt sharpening) because the model ignores the
  instruction, so 34.2 stays validator-side. A heading-match lever (34's A.3) remains NOT NEEDED here
  (P2's citation ≠ the heading).
