## Context — why this slice

The only destructive workspace-reset path is **Replace** in the results header. Today it gates on a
native `window.confirm()` ([ParserResultsShell.tsx:110-140](../../../src/components/lease/ParserResultsShell.tsx#L110-L140)):

```ts
const confirmed = window.confirm(
  'Reset workspace? This removes the uploaded lease, extracted clauses, and red flags. This cannot be undone.',
);
if (!confirmed) return;
// revoke pdfUrl → getPdfBinaryRepository().delete(lease_id) → resetParser() → onReplace()
```

`window.confirm` is three liabilities at once:

- **UX (Don Norman / Apple HIG / Dieter Rams):** the OS confirm is unstyled chrome that breaks the
  workspace's visual language, can't carry a 44px touch target / visible focus ring / reduced-motion
  affordance, and reads identically to a benign prompt — it doesn't *look* like an irreversible reset.
- **A11y (WCAG):** we surrender all control of focus, semantics, and announced consequence copy to the UA.
- **Testability (Kent C. Dodds):** happy-dom does **not** implement `window.confirm`, so the three
  Replace tests ([ParserResultsShell.test.tsx:73-122](../../../src/components/lease/ParserResultsShell.test.tsx#L73-L122))
  `vi.stubGlobal('confirm', …)` and assert `confirmSpy.mock.calls[0][0]` — they test a browser API the
  runtime lacks, not anything a user can perceive. **And the IndexedDB-eviction invariant
  (`getPdfBinaryRepository().delete(lease_id)`) is currently UNVERIFIED** — happy-dom has no
  `indexedDB`, so `getPdfBinaryRepository()` returns the `NoopPdfBinaryRepository` and the `delete()`
  call is silently swallowed. This slice closes that gap.

This is a **bug-triage-class polish** carry from Sprint 28: small surface, no behaviour change to the
destructive sequence, strict a11y, and a net test-coverage gain.

## The design panel — convergence

All four lenses agreed on the spine, so it is **not** an open decision:

1. **Substrate = native `<dialog>` + `showModal()`/`close()`** (mirror `PdfFocusDialog`), **not** a
   hand-rolled `div` like the FAB. The browser gives focus-trap, Esc-to-close, `::backdrop` scrim, and
   modal SR semantics for free — fewer ways to get the trap wrong in ~90 LOC. *(WCAG, SOLID, Norman.)*
2. **`role="alertdialog"`** (override the implicit `dialog` role) — a consequential yes/no decision is
   the WAI-ARIA `alertdialog`, which tells SR users it interrupts. `aria-modal="true"`,
   `aria-labelledby`→title, **`aria-describedby`→the consequence sentence** (the warning a SR user
   must hear on open — `PdfFocusDialog`'s missing piece). *(WCAG, Norman, SOLID.)*
3. **Boundary (Uncle Bob):** the dialog is a **dumb presenter**. It must **not** import
   `getPdfBinaryRepository`, must **not** touch Blob URLs, must **not** know the word "lease." It
   renders a question and calls `onConfirm` / `onCancel`. The destructive sequence stays in the shell.
   This is Single Responsibility + Dependency Inversion.
4. **Split `handleReplace()`** into `requestReplace()` (opens the modal — intent capture) and
   `confirmReplace()` (the **byte-for-byte existing** destructive body). The Sprint 28.9 rationale
   comments are load-bearing per CLAUDE.md and move *with* the destructive body.
5. **Initial focus = Cancel** (the safe action), never the destructive confirm — a stray Enter must
   dismiss, not destroy. *(Norman, WCAG.)*
6. **Escape / backdrop-click / Cancel all = cancel path** and run **none** of revoke/evict/reset. Only
   the explicit destructive button runs them. A destructive action must never be confirmable by an
   outside click. *(Norman, WCAG, Kent.)*
7. **Focus-return to `results-replace-button` on close**, via an explicit effect mirroring
   AssistantFab:238-248 — happy-dom won't auto-return, and `PdfFocusDialog` omits this. *(WCAG, Norman.)*
8. **Colour-never-alone (CLAUDE.md):** destructive button = `bg-danger-600 text-white` + an explicit
   **verb label** + an icon (`aria-hidden`). Cancel = neutral bordered button. *(WCAG, Norman.)*
9. **Reduced motion:** entrance gated `motion-safe:*` with a paired `motion-reduce:animate-none` /
   `motion-reduce:transition-none`; pin with a `className` regression assertion (precedent
   `ParserLandingShell.test.tsx:113`). Calm, ~150ms, no bounce. *(WCAG, Rams.)*
10. **Tokens only (Rams):** `surface-card`/`surface-elevated`, `border-neutral-*`, `--color-backdrop`,
    the standard `focus-visible:ring-2 ring-accent-300 ring-offset-2`, `shadow-xl` max. No new abstractions.
11. **Copy:** carry the existing three-noun enumeration + "cannot be undone" — Norman flagged it as
    *already-good* feedback. **Do NOT reuse** `"Your lease review was preserved"` — that aria-live
    string belongs to Clear-chat and would be a mental-model lie here (this destroys the review).

## Spec

### New file — `src/components/lease/ConfirmDialog.tsx` (presentational primitive, ~80-90 LOC)

A generic, domain-free confirm dialog. Props:

```ts
interface ConfirmDialogProps {
  open: boolean;
  title: string;            // accessible name (aria-labelledby)
  description: string;      // consequence copy (aria-describedby)
  confirmLabel: string;     // verb+object, e.g. "Reset workspace"
  cancelLabel?: string;     // default "Cancel"
  destructive?: boolean;    // confirm button → bg-danger-600 + warning icon
  onConfirm: () => void;
  onCancel: () => void;
}
```

Responsibilities (and **only** these):

- Render a native `<dialog data-testid="confirm-dialog" role="alertdialog" aria-modal="true">`,
  driven imperatively by `showModal()`/`close()` exactly like `PdfFocusDialog` (the proven pattern).
- `aria-labelledby={useId titleId}` + `aria-describedby={useId descId}`.
- Bridge the native `close` event → `onCancel` (mirror `PdfFocusDialog.tsx:54-60`). So Escape =
  Cancel automatically.
- Backdrop dismiss = Cancel: a click whose target **is** the `<dialog>` element itself (i.e. outside
  the inner panel) calls `onCancel`. Clicks inside the panel do not.
- On open, focus the **Cancel** button (explicit `ref.focus()` in the open effect — `autofocus`
  alone is unreliable in happy-dom).
- On close, return focus to the element that was focused when it opened (capture
  `document.activeElement` on open; `.focus()` it on close — mirror AssistantFab:238-248).
- Buttons: Cancel = neutral bordered (`border-neutral-200 bg-surface-card hover:bg-surface-muted …`);
  Confirm = `destructive ? 'bg-danger-600 text-white …' : 'bg-accent-…'`. Both `min-h-11`
  (≥44px) + `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent-300
  focus-visible:ring-offset-2`. When `destructive`, render a `TriangleAlert` (lucide) `aria-hidden`
  icon on the confirm button so colour is never the sole destructive signal. **Cancel left, Confirm
  right** (HIG affirmative-trailing; the explicit label carries the weight, not the position).
- Scrim/panel use `backdrop:bg-backdrop` + `bg-surface-elevated shadow-xl`, entrance
  `motion-safe:animate-…` + `motion-reduce:animate-none`. A small centred panel: title + one
  paragraph + two buttons. Nothing else.

It imports **nothing** from `@/lib/lease/*`, no Blob APIs, no contexts → needs no providers in tests.

## Decisions to lock at the Spec-QA gate

- **D1 — primitive scope/name (the one real fork).** **Generic `ConfirmDialog`** (recommended — the
  Uncle Bob answer: DIP, no domain leak, reusable by any future destructive confirm) **vs.**
  lease-specific `ReplaceConfirmDialog` with a `leaseName?` prop (smaller surface, YAGNI-friendly since
  Replace is the *only* destructive confirm today). I lean **generic** because it keeps the dialog
  ignorant of the domain and prevents a third bespoke copy of dialog-a11y machinery — but it is a
  defensible judgment call and yours to make.
- **D2 — confirm button icon.** A generic `ConfirmDialog` should render a **generic** `TriangleAlert`
  (domain-free) rather than the Replace-specific `RotateCcw`. The verb label "Reset workspace" already
  carries the specific meaning. (If we pick the lease-specific component in D1, `RotateCcw` is fine.)
- **D3 — title wording.** Keep the existing **"Reset workspace?"** (Norman praised the current copy;
  continuity) vs. Norman's alternative **"Replace this lease?"** (ties to the trigger button labelled
  "Replace"). I recommend keeping **"Reset workspace?"** + body verbatim. Minor; flagging the
  trigger-says-"Replace" tension for you.
- **D4 — `next-env.d.ts` (batch item 2).** Gitignore it + `git rm --cached` to stop the perpetual
  dirty-status churn (recommended) vs. keep it committed (Next.js's documented default). See the
  dedicated section below — this is the second, code-free item in the batch.

Everything in **Convergence** (1-11) is locked by the panel, not re-opened here.

## WCAG acceptance checklist (the implementation must satisfy all)

1. `role="alertdialog"` + `aria-modal="true"` + `aria-labelledby`(title) + `aria-describedby`(consequence).
2. Focus trap via native `showModal()` — do not re-implement; Cancel + Confirm are the two tab stops.
3. Initial focus on **Cancel** (safe action) on open.
4. Escape → `onCancel` via the native `close` event bridge; Escape **never** confirms.
5. Focus returns to `results-replace-button` on close (explicit effect; verified by test).
6. Both buttons `min-h-11` (≥44px).
7. Repo-standard `focus-visible:ring-2 ring-accent-300 ring-offset-2` on both buttons.
8. Colour-not-alone: confirm = `bg-danger-600 text-white` + verb label + `TriangleAlert` icon
   (`aria-hidden`). Contrast white-on-`#b33232` ≈ 5.9:1 (AA) — verify.
9. Reduced motion: `motion-reduce:animate-none` (+ `motion-reduce:transition-none` if a transition is
   used); pinned by a `className` regression assertion.
10. Backdrop via the `backdrop:bg-backdrop` token (no per-class dark variant).

## Batch item 2 — stop the `next-env.d.ts` churn

`next-env.d.ts` is **tracked** but Next.js **autogenerates** it. The working-tree diff is purely the
dev-vs-prod routes-types import path swapping back and forth:

```diff
-import "./.next/dev/types/routes.d.ts";   // after `next dev`
+import "./.next/types/routes.d.ts";        // after `next build`
```

So every `npm run dev` / `npm run build` re-dirties it — noise in `git status` and in every diff.
**Recommendation (D4):** `git rm --cached next-env.d.ts` + add `next-env.d.ts` to `.gitignore`
(near the existing `.next/` entry at line 10). This is a one-line, code-free hygiene fix that ends the
churn. **Caveat:** Next.js's docs say to commit `next-env.d.ts`; for a single-app repo whose only diff
is the autogenerated routes path, ignoring it is the common, lower-noise choice — but it is your call,
hence D4. No tests; verified by a clean `git status` after `npm run build` then `npm run dev`.

## Spec-QA — gaps & risks

- **Risk: happy-dom `<dialog>` fidelity.** No real `showModal` focus semantics — mitigated by the
  PdfFocusDialog polyfill + the explicit focus-return effect (we don't *rely* on UA behaviour). The
  focus-return test (#6) is kept lenient; the side-effect tests are the contract.
- **Risk: backdrop-dismiss detection.** Distinguishing an on-`<dialog>` click (backdrop) from a panel
  click needs `e.target === dialogEl`. If it proves flaky in happy-dom, prefer omitting test #5 over
  faking it (Kent), and keep Escape (#4) as the keyboard-equivalent dismissal coverage.
- **Risk: `bg-danger-600` as a solid fill is new** — the token is used today only as a tint
  (`bg-danger-100`) + text colour. The token itself exists (`globals.css:96`) and white-on-`#b33232`
  passes AA (~5.9:1). No new token, just a new combination.
- **Non-goal creep:** this slice does **not** add a confirm to "Clear assistant chat" (that flow is
  non-destructive by construction — it preserves the lease). If D1 picks the generic `ConfirmDialog`,
  that future reuse is *enabled*, not *built* here.

## Out of scope

- Any change to the destructive sequence itself (revoke/evict/reset semantics) — byte-for-byte preserved.
- A confirm on Clear-chat; a shared `Button` primitive; portal libraries; new tokens.
- Surface estimate: ~80-90 LOC new component + ~3 tests migrated + ~6 new tests + ~10 LOC shell wiring +
  a 1-line `.gitignore` change. No new deps.

## Post-spec addendum (shipped) — calm enter/exit motion

After review, a calm **fade + subtle scale, both directions** was added to the dialog (user request).
No claymorphism/glassmorphism (legal-product guidance + Rams restraint): the surface stays opaque
conservative-Material; the change is motion, not material. Implemented as pure CSS on the dialog
element via Tailwind v4 `starting:` + `transition-discrete` (`@starting-style` + `allow-discrete`) so
the leave defers `display:none` until the transition finishes — zero deps, zero new state, no timers,
and a no-op under `prefers-reduced-motion`. Full rationale, tests, and live frame-sampling proof are in
[`28.15-impl.md`](28.15-impl.md) → *"calm, symmetric enter + exit motion."*
