# Sprint 33.A + 33.B — Chat Trim + Right-Pane Verdict (Co-Dependent)

## Context

Sprint 33.0 fenced off conversation-id staleness. Sprint 33.A + 33.B retire the chat's redundant scan-summary surface AND give the right pane the synthesized verdict it needs to stand alone. They ship as one release because the brainstorm Appendix locked them as co-dependent — removing the chat's table without the right-pane verdict would regress the user's prioritisation experience.

The live evidence motivating the slice: on a clean lease whose actual gradings were **1 LOW + 10 OK + 4 errored**, the model's chat text fabricated a horror-show table claiming **10 HIGH-severity findings**. The model invented those issues to fill the `scanCompleteSummarySection` table format it was instructed to produce, ignoring the actual `grade_clause_severity` tool results.

**A4.** ChatUI appends a deterministic **scan-complete receipt** as a synthetic message in the transcript when the lifecycle transitions to `review_ready` AND `gradings.length > 0`. The synthetic content is **computed client-side, NOT by the model**:


Where N is the count of valid gradings + errored gradings (i.e. all clauses the scan attempted). The receipt appears exactly once per scan completion and persists in the transcript thereafter.

### Sprint 33.B — right pane absorbs the verdict

**B1.** New helper `src/lib/lease/scan-verdict.ts` exporting `computeScanVerdict(gradings, ungradedCount)`:

```ts
export type VerdictTier = 'high' | 'medium' | 'low' | 'ok' | 'idle';
export interface ScanVerdict {
  tier: VerdictTier;
  headline: string;
  topClauseTitle: string | null;
}
export function computeScanVerdict(
  gradings: readonly GradingResult[],
  ungradedCount: number,
): ScanVerdict;
```

Pure function. Picks the highest tier present in `gradings`. Picks the top-1 clause title from that tier (lexicographic-stable; if multiple, the first). Headlines:

| tier | headline pattern |
|---|---|
| `high` | `"High risk — {N} findings, biggest concern is {topClauseTitle}."` |
| `medium` | `"Medium risk — {N} findings, biggest concern is {topClauseTitle}."` |
| `low` | `"Low risk — {N} findings reviewed."` (no top-clause callout for low) |
| `ok` (all OK) | `"Lease is balanced — no high-severity issues found."` |
| `idle` | empty string (no headline) |

Top-clause title uses the existing `clauseLabel(result)` helper from `src/components/lease/grading.ts`. Fully unit-testable: red tests cover each tier + tie-breaking.

**B3.** [src/components/lease/RedFlagReport.tsx](../../../src/components/lease/RedFlagReport.tsx) — add an **errored-clause line** below the cards (or below the summary row, TBD during impl). Renders only when at least one grading event has shape `{ error: … }` (ungraded). Copy:

## Spec QA — gaps & risks

- **Risk: model still produces a table despite the prompt rewrite.** The new wording is imperative and the auto-scan turn's `tool_choice` is `'any'` for iteration 1 only — the FINAL iteration (where the summary is written) uses `'auto'`. We can't force-block the model from producing a table. Mitigation: the prompt explicitly forbids it ("MUST NOT reproduce the findings as a markdown table, bullet list, or any other multi-row format"). If empirical reproduction shows the model still drifts, we add an output-filter on the client (regex/markdown-table detector → strip + replace with the deterministic receipt). Tractable follow-up if needed.
- **Risk: ScanTimeline gating breaks user-initiated re-scans.** A user typing "scan again" in the FAB is a normal multi-turn conversation; the ScanTimeline should still render. The gate is per-message provenance (first turn of auto-scan conversation only), not a global toggle. Tests cover both paths.
- **Risk: verdict headline misleading on errored-heavy scans.** If 14 of 15 clauses errored and 1 returned `ok`, the headline says "balanced." Mitigation: ungraded line lives next to the headline so the user sees both signals. Headline + ungraded count together = honest picture.
- **Risk: chip set regresses the "Explain this clause" affordance that Sprint 27 added.** Mitigation: per Sprint 29.3, the FAB context bar (Focused on: clause · §N) is the new affordance for clause-specific Q&A. The "Explain the highest-risk clause" chip handles general explain-top intent; per-clause Explain happens via clicking a card's button (already wired in RedFlagReport — Sprint 26c).
- **Risk: the scan-complete receipt double-fires (once per render).** Mitigation: gate on a flag in ChatStreamContext (e.g. `scanCompleteReceiptShownForConversation`) that tracks which conversations have had the receipt fired. Refresh resets it. Tests pin "fires exactly once per conversation transition to review_ready."
