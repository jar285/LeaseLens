# Sprint 33.A + 33.B — Implementation Notes & QA Report

## Context summary

Sprint 33.0 fixed conversation-id staleness at the server boundary. The slice landed cleanly but surfaced a deeper issue on the live re-verify of the next upload: the FAB chat was *still* contradicting the right-pane cards. The Sprint 32.2.0 per-tool diagnostic confirmed the actual gradings were correct (mostly OK + 1 LOW); the chat's markdown table fabricated **10 HIGH-severity violations** the tool results never produced. The model was filling the prescribed table format with invented findings.

Sprint 33.A + 33.B retires the prescribed table and gives the right pane the verdict it needed to stand alone. They ship together — removing the chat's table without absorbing the verdict in the pane would regress the prioritisation experience.

## What was completed

### Sprint 33.A — chat is Q&A only

**A1 — system-prompt rewrite (Sprint 23f Phase 4 section retired).** [system-prompt.ts:159-168](../../../src/lib/chat/system-prompt.ts#L159-L168) — the "scan-complete summary as a markdown TABLE" instruction is replaced with a single-sentence acknowledgement contract: *"You MUST NOT reproduce the findings as a markdown table, bulleted list, numbered list, or any other multi-row format. Your reply on the auto-scan turn is a single short sentence acknowledging completion and inviting the user to ask a follow-up — e.g. 'Done — see the findings on the right; ask me about any clause.'"*

**A2 — scan-agnostic Q&A chip set.** [AssistantFab.client.tsx:86-126](../../../src/components/chat/AssistantFab.client.tsx#L86-L126) — the Sprint 29.4 three-way lifecycle-driven chip split (`MID_SCAN_CHIPS` / `REVIEW_READY_CHIPS`) is collapsed into a single `QA_CHIPS` set: `explain-top-finding`, `draft-biggest-concern-email`, `compare-to-nj-law`, `what-to-fix-first`. The chat no longer narrates the scan, so the chip set is the same whether the scan is mid-flight or complete. Empty-state subhead collapses too: when a lease is active, *"Ask about any clause, citation, finding, or what to negotiate."*

### Sprint 33.B — right pane absorbs the verdict

**B1 — pure verdict helper.** New file [src/lib/lease/scan-verdict.ts](../../../src/lib/lease/scan-verdict.ts). `computeScanVerdict(gradings, ungradedCount)` returns a `{ tier, headline, topClauseTitle }` triplet. Picks the highest severity tier present, picks the top-1 clause by smallest `clause_index` (deterministic tiebreaker), produces a tier-specific headline ("High risk — N findings, biggest concern is X", "Medium risk — …", "Low risk — N findings reviewed.", "Lease is balanced — no high-severity issues found.", or empty for idle). Pure function, fully unit-testable.

**B2 — verdict headline in the right pane.** [RedFlagReport.tsx](../../../src/components/lease/RedFlagReport.tsx) renders the synthesized headline above the existing severity-count strip when `verdict.tier !== 'idle'`. Computed in code, NEVER by the model — by construction it cannot drift from the cards.

**B3 — ungraded-clause hand-off.** [RedFlagReport.tsx](../../../src/components/lease/RedFlagReport.tsx) adds a `[data-testid="red-flag-ungraded-line"]` button below the cards when at least one `grade_clause_severity` event came back as an error envelope (e.g. citation grounding rejected). Click opens the FAB with a pre-filled "Why couldn't these clauses be graded?" prompt — the chat stays the consistent "ask why" surface.
