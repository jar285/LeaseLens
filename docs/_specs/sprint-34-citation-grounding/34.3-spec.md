# Sprint 34.3 — Citation grounding: markdown-aware + cross-chunk matching (P3-class)

> Draft for the Spec-QA gate before any TDD. Continues Sprint 34's diagnose→fix loop. Targets the
> "P3-class" residual rejections — and the investigation reframes what P3 actually is.

## Context — what the investigation found

Sprint 34.2 classified `"Marini v. Ireland, 56 N.J. 130 (1970)"` against `repair-and-deduct#section:1`
as a **genuine** grounding miss (external authority absent → correctly rejected). **That was wrong.**
The real corpus shows `repair-and-deduct.md` §"The remedy" (→ `#section:1`) literally contains:

```
The remedy was established in *Marini v. Ireland*, 56 N.J. 130 (1970).
```

The italic `*` between "Ireland" and the comma makes the lowercased body read
`…marini v. ireland*, 56 …`, so `haystack.includes("marini v. ireland, 56 …")` fails. **The citation
is grounded — it's a markdown-emphasis false-negative.** This also explains the intermittency:
`habitability-warranty.md` and `indemnification-clauses.md` bold the **whole** citation
(`**Marini … (1970)**` — markers outside, clean substring, matches), while `repair-and-deduct.md`
italicises only the case name (`*Marini v. Ireland*,` — marker mid-citation, no match).

So "P3-class" is really three things:

| | Pattern | Disposition |
|---|---|---|
| **P3a** | Citation present **modulo `*`/`_`/`` ` ``** emphasis in the chunk body | **Recover (E.1)** — dominant real case |
| **P3b** | Citation verbatim in a **different retrieved chunk** than the one labeled in `chunk_id` | **Recover (E.2, optional)** |
| **P3c** | Citation in **no** retrieved chunk (genuine absence / fabrication) | **Stays rejected** — grounding intact |

This is a **Source-Grounded AI** refinement: the grounding guarantee is "the citation text appears in
the retrieved context the model was shown." Emphasis markers are presentation, not content; the cited
chunk vs the retrieved set is an attribution detail. Neither should sink a grounded citation — but a
citation absent from the entire retrieved context still must reject.

## Spec

### Invariants (carried — must not break)

- **Fabrication / genuine-absence still rejects** (P3c): a citation not in any retrieved chunk even

- `NODE_ENV`-gated `[chat-diag s32.2-reject]` logging unchanged.

### Lever E.1 — markdown-emphasis-aware normalisation (PRIMARY)

Add `stripEmphasis(s)` (remove `*`, `_`, `` ` ``) and fold it into the grounding normaliser used by A.2,
applied to **both** the chunk body (haystack) and each citation part (needle), alongside the existing
lowercase + whitespace-collapse:

```
normaliseForGrounding(s) = s.toLowerCase().replace(/[*_`]/g, '').replace(/\s+/g, ' ').trim()
```

Stripping only *removes* characters, so a citation can newly match only if the sole difference was
emphasis markers — i.e. only genuinely-present-modulo-formatting citations pass; P3c still fails.
~2 lines + a helper. Recovers the observed Marini-vs-repair-and-deduct reject and any bold/italic-broken
citation. (Reuse the same normaliser in D.2's title compare for consistency.)

### Lever E.2 — cross-chunk body match (SECONDARY, separable — see scope decision)

Today A.2 checks only the `cited` chunk (the one the model labeled in `chunk_id`). The model was shown
all `RETRIEVAL_K` chunks, so a citation verbatim in **any** of them is grounded in the retrieved
context. Extend: if no part matches the cited chunk, scan the other retrieved chunks; if a part matches
chunk Y (after E.1 normalisation), accept and **re-point `chunk_id` to Y** so the stored record matches
where the evidence lives. Still rejects citations in no retrieved chunk. `chunk_id` drives only internal
grounding (nothing tenant-visible diverges), so re-pointing is safe. Cost: a handful of extra `includes`
over ≤4 short strings — negligible.

### Lever E.3 — graceful degradation (DEFERRED; documented for opt-in)

Today a citation reject discards the whole grading (severity + reasoning + recommended_action) → the
clause shows "couldn't be graded." A Michael-Nygard alternative: on a citation miss, keep the grading
and substitute the cited chunk's humanised label (treat ungrounded-citation like missing-citation).
**Recommend defer:** it weakens the source-grounding contract (surfacing a finding whose citation the
model got wrong) in a legal-adjacent tool, and E.1+E.2 already recover the formatting/attribution cases
*without* weakening grounding. Out of scope unless you opt in.

### Gate order inside validateGrading (after this slice)

retrieved-check → D.1 (pointer) → **A.2 (E.1-normalised body part match) → E.2 (same, across all retrieved chunks, re-point)** → D.2 (title) → reject (P3c).

## Spec QA — gaps & risks

- **Scope decision for you:** **E.1-only** (minimal, fixes the observed dominant case) **vs E.1+E.2**
  (also covers mis-attributed chunks). I lean **E.1+E.2** — both are grounding-preserving and the
  retrieved set is already in hand — but E.1-only is a clean, smaller slice if you prefer. E.3 deferred.
- **Over-stripping risk (E.1):** removing `*`/`_`/`` ` `` could in theory merge tokens (`a*b`→`ab`).
  Legal citations don't contain mid-word emphasis, and stripping is symmetric; the fabrication guard
  (can only remove chars) bounds the risk. Low.
- **Doesn't fix retrieval recall:** if the authority is in a chunk that was never retrieved (not in the
  K=4), neither E.1 nor E.2 helps — that's a retrieval-quality concern (raise K / better ranking),
  out of scope here and noted as a carry.
- **Corpus consistency (orthogonal):** the corpus bolds citations inconsistently (`**whole**` vs
  `*name*,`). E.1 makes the validator robust to that, so a corpus-normalisation pass is NOT required —
  but standardising emphasis in the corpus would be defensible separate hygiene (ties to the earlier
  corpus-provenance idea).
